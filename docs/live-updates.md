# 중계 전송과 장면 속도

시즌 후반에는 과거 경기와 일상이 누적되어 중계 갱신마다 전체 공개 시즌 기록을 전송하는 비용이 커진다. 8월 재현 저장의 공개 시즌은 약 5.5MB, 원본/기준/정산 대기를 포함한 저장은 약 16.7MB였다. 세트 사이 전략 적용은 공개된 세트를 재검증하기 위해 기존 방식으로 다시 계산하지만, 다음 세트에 필요 없는 전체 시즌 기록을 다시 내려보내지는 않는다.

## 선택적 중계 갱신

- 초기 접속과 일반 API는 기존 room 전체 응답을 유지한다.
- 중계 폴링의 liveUpdate=1, liveId, seasonId, turn이 현재 서버 중계와 일치하면 roomPatch로 응답한다.
- set-strategy에서 liveUpdate=true와 같은 식별자를 보낸 경우에도 전략 적용 후 roomPatch를 반환한다. 구형 클라이언트는 계속 전체 응답을 받는다.
- 패치는 기존 roomView의 권한·메시지·초상화·현재 공개된 중계 투영을 그대로 사용하면서 season만 복제·전송에서 제외한다. 서버 기준/정산 대기 방이나 미래 결과는 포함하지 않는다.
- 클라이언트는 현재 방·계정·시즌·턴·중계 식별자를 검증하고 이미 받은 season 객체를 그대로 유지한다. 식별자가 맞지 않으면 전체 방을 다시 읽는다. 낮은 revision의 늦은 응답은 화면을 이전 세트로 되돌리지 않는다.
- 정산이 끝나 새 날짜로 넘어가면 서버가 전체 응답으로 돌아가 순위·기록·보상·일상을 갱신한다. 같은 날의 다른 시리즈로 넘어갈 때는 새 중계 투영을 사용한다.
- 16KiB 이상 JSON은 클라이언트가 허용하면 gzip(level 1)으로 압축한다. gzip;q=0과 identity는 압축하지 않는다. Cache-Control no-store와 기존 인증을 유지한다.

합성 후반 시즌 API 검사에서 공개 상태 1,734,341바이트 → 전략 적용 응답 43,365바이트로 압축 전 97.5% 감소했다. 브라우저 검사에서는 2,037,378 → 54,609바이트였다. 실제 응답 크기는 진행된 경기·대화·사진에 따라 달라진다.

## 지연된 화면의 장면 건너뛰기 방지

공개 API의 advanceLiveMatch는 maxFrames=1로 진행한다. 오래 지난 wall clock을 한꺼번에 따라잡지 않으며, 장면을 진행한 시각에 다음 표시 간격을 다시 맞춘다. 여러 참가자가 동시에 조회해도 같은 간격 안에 장면이 계속 빨라지지 않는다. 마지막 넥서스를 공개한 뒤 다음 간격에만 정산한다. 테스트/복구용 직접 호출의 기존 무제한 진행 옵션은 유지한다.

전략 선택 중에는 준비 표시를 즉시 보여주고 중복 클릭·폴링 렌더를 막는다. 응답을 받은 뒤 다음 세트를 한 번 렌더한다. 전략 재계산을 위한 불필요한 전체 방 복사 한 번도 제거했다. 기존 세트의 역학 검증과 원본 세트 유지, 구버전 경기 규칙 고정, 일회 보상은 바꾸지 않는다.

검증: npm test, npm run check, /tmp 임시 DB의 live-performance-browser.mjs. API 검사는 큰 과거 기록·압축 협상·식별자 불일치·권한·한 장면 진행·미래 비공개를 확인하며, 브라우저 검사는 준비 표시·중복 방지·작은 응답·지연 후 장면 유지까지 확인한다.

## 다른 탭에서 중계 진행

진행 중인 중계는 document.hidden 상태에서도 작은 중계 갱신을 계속 조회한다. 숨겨진 화면에서는 전체 DOM 렌더를 미루고 데이터를 보관하며, 화면으로 돌아오면 즉시 새 상태를 표시하고 현재 중계를 따라간다. 배경 조회는 보통 1.4초 간격으로 제한하며, 세트 사이 전략 대기는 서버의 기존 intermission 규칙을 그대로 따른다. 중계가 끝난 뒤에는 배경에서 일반 날짜를 자동 정산하지 않는다. 브라우저 자체가 탭을 강제로 정지/폐기한 경우 타이머는 중단될 수 있으므로 복귀 시 즉시 동기화한다.

브라우저 검사는 숨김 상태를 제어하여 배경 응답 수신·렌더 지연·복귀 반영·다음 세트의 수동 전략 대기를 확인한다.

## 빠른 채팅 갱신

열린 채팅창과 대기실 대화는 별도 /messages?after=ID 요청으로 새 메시지만 500ms 간격으로 조회한다. 서버는 방 참가 여부를 SQL에서 확인하고 전체 시즌 복제·진행·저장 없이 기존 개인 대화 권한과 자동 메시지 필터를 적용한다. 새 메시지가 없으면 304를 반환한다. 숨겨진 탭에서는 이 조회를 쉬고 중계 조회만 유지한다.

응답은 현재 방과 계정이 일치할 때만 병합하고 최근 200개를 유지한다. 늦게 도착한 전체 방 응답에도 먼저 도착한 새 대화를 보존한다. 대화 로그만 갱신하므로 작성 중인 입력과 스크롤을 유지하며 경기 화면을 다시 그리지 않는다.

경기 불판은 새 공개 장면과 함께 갱신되므로 기본 장면 간격을 1400ms에서 1000ms로 줄였다. 기존 기본 속도 중계도 현재 커서와 다음 장면까지의 진행 비율을 보존해 전환하며, 오랜 경과 시간은 최대 한 장면까지만 반영한다. LIVE_STEP_MS 사용자 설정은 유지한다.
