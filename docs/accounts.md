# 초대 전용 계정

아이디·비밀번호로 로그인한 사용자만 게임 API를 사용할 수 있다. 새 가입에는 사용되지 않은 사이트 초대장이 필요하며, 계정 닉네임은 가입 때 정하고 내 계정에서 변경한다. 사이트 초대장과 시즌 방 초대코드는 별도다.

## 최초 관리자 설정

1. 운영 환경에 `FIRST_TEAM_ADMIN_INVITE`를 24~128자의 충분히 긴 무작위 값으로 설정한다. 암호 관리자의 랜덤 문자열 생성기를 사용해도 된다. 이 값을 소스, 공개 채팅, 커밋에 넣지 않는다.
2. 서버를 시작하거나 재배포한다. 첫 관리자 계정이 없을 때만 해당 값으로 관리자용 일회용 초대장을 준비한다.
3. 사이트의 **초대 가입**에서 이 코드를 입력하고 본인의 아이디·비밀번호·닉네임을 정한다. 가입한 계정은 관리자가 된다.
4. 로그인 후 **초대장 관리 → 초대장 발급**에서 친구에게 줄 링크를 만든다. 친구 초대장의 유효기간은 1·7·30일이며 한 번만 쓸 수 있다.
5. 관리자 가입 후 bootstrap 환경변수를 제거해도 기존 계정은 유지된다. 같은 bootstrap 코드를 유지해도 재사용되지 않으며, 관리자가 존재하면 추가 bootstrap 관리자 초대장을 만들지 않는다.

Render Blueprint 신규 배포는 `render.yaml`의 `generateValue: true`로 이 값을 생성한다. Render 대시보드 환경변수에서 본인만 값을 확인해 최초 가입에 사용한다. **이미 운영 중인 Render 서비스는 저장소 push만으로 환경변수가 추가된다고 가정하지 말고 직접 설정한다.** 최초 코드를 쓰기 전에 7일이 지나 만료되었다면, 관리자가 없는 상태에서 새로운 무작위 값으로 변경해 새 초대장을 준비한다.

이 초기 절차는 첫 방문자를 관리자로 만드는 방식이 아니다. 환경변수도 기존 관리자도 없으면 공개 방문자는 관리자나 가입 초대장을 만들 수 없다.

## 저장과 이전 기록

계정, 비밀번호 해시, 접속 세션, 초대장 사용 내역은 기존 `DATA_FILE` SQLite에 함께 저장한다. 기존 `users`, 캐릭터 슬롯, 방, 채팅은 삭제하거나 초기화하지 않는다. 예전 브라우저의 `ft_session` 쿠키가 남아 있다면 그 브라우저에서 초대 가입할 때 기존 사용자 ID와 기록을 새 계정에 연결하고, 옛 익명 접속 토큰은 무효화한다. 이미 잃어버린 쿠키나 삭제된 DB를 복구하는 기능은 아니다.

로그인 이후 같은 아이디·비밀번호를 다른 기기에서 사용하면 동일한 캐릭터 슬롯과 참가 방을 불러온다. 로그아웃은 해당 기기의 세션을 취소한다. 비밀번호 변경은 다른 기기 세션도 취소한다. 계정 닉네임 변경은 대기실·현재 방의 오너 이름에도 반영하며, 지난 채팅에 남은 당시 이름은 보존한다.

**Render 무료 인스턴스의 `/tmp` DB는 영구 저장이 아니다.** 이 설정이면 재배포 때 계정과 초대장까지 사라질 수 있다. 운영 계정을 유지하려면 영구 디스크 또는 별도 영구 DB가 필요하다. 이 변경은 유료 인스턴스나 디스크를 자동 구매하지 않는다. 기존 서비스에 기록이 있다면 재배포 전에 운영자가 해당 DB를 백업·이전해야 한다.

## 인증 동작

- 비밀번호: 사용자별 랜덤 salt를 가진 scrypt 해시. 원문 비밀번호는 저장하지 않는다.
- 접속: 서버에 해시만 저장하는 랜덤 세션 토큰, 만료 30일, 최대 10기기. 쿠키는 HttpOnly·SameSite=Strict이며 운영 HTTPS에서는 `COOKIE_SECURE=1`을 사용한다.
- 초대장: 랜덤 토큰의 해시만 저장, 만료·일회 사용·취소 지원. 가입과 사용 처리는 같은 DB 트랜잭션으로 완료해 중복 가입을 막는다. 일반 초대장으로 관리자 권한을 요청해도 부여하지 않는다.
- 관리자 권한은 서버에서 매 요청 확인한다. 사이트 관리자도 참가하지 않은 시즌 방을 조회할 수 없다.
- 로그인·가입 시도 횟수를 제한한다. 신뢰하는 단일 역방향 프록시 뒤에서만 `TRUST_PROXY=1`을 사용한다. Render 설정은 마지막 forwarded 주소를 클라이언트 주소로 사용한다.
- 초대 링크는 로그인 화면이 읽은 뒤 URL에서 제거하며 Referrer-Policy는 no-referrer다. 비밀번호·초대장 원문·세션 토큰은 세션 JSON, 시즌 내보내기, 발급 목록에 넣지 않는다.

## 검증

`npm test`는 초대 가입·권한·세션·동시 초대장 사용·만료·기존 저장 연결과 전체 게임 API를 검증한다. 기존 API 회귀 검사는 임시 DB에 실제 초대장을 만들어 가입하며, 서버에 인증 우회 모드를 추가하지 않는다.

브라우저 검사는 별도의 임시 `DATA_FILE`, `BASE_URL`, 테스트용 `FIRST_TEAM_ADMIN_INVITE`를 사용한 서버에서 `node test/auth-browser.mjs`로 실행한다. 기존 `test/browser-smoke.mjs` 등은 임시 DB에 실제 초대 계정을 만드는 테스트 헬퍼를 사용하므로 `DATA_FILE`이 필요하다. 운영 DB에서 테스트하지 않는다.
