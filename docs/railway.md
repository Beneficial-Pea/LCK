# Railway로 공개 주소 만들기

현재 게임 소스는 클라우드 작업 공간에 있고, GitHub 저장소에는 아직 업로드하지 않았습니다. Railway 배포도 아직 실행하지 않았습니다. 다음 단계는 사용자의 GitHub/Railway 계정에서 진행합니다.

1. 먼저 이 프로젝트 파일을 `Beneficial-Pea/LCK`의 `main` 브랜치에 올립니다. `.data`, `.env`, `test-results`는 올리지 않습니다. GitHub에 올리는 작업은 이 문서 작성만으로 실행되지 않습니다.
2. [Railway](https://railway.com/)에 GitHub 계정으로 로그인합니다.
3. 새 프로젝트에서 GitHub 저장소로 배포하는 항목을 선택하고 `Beneficial-Pea/LCK`를 연결합니다. 저장소 목록에 없다면 Railway의 GitHub 앱에 해당 저장소 접근을 허용합니다.
4. 게임 서비스에 **Volume**을 추가하고 마운트 경로를 `/data`로 지정합니다. 여기에 참가자·캐릭터 슬롯·방·시즌·채팅 SQLite 파일이 저장됩니다. Volume을 삭제하면 세이브가 사라질 수 있습니다. 서비스 인스턴스/복제 수는 **1개**로 유지합니다.
5. `Dockerfile`과 `railway.json`이 자동 빌드 설정으로 사용됩니다. `PORT`는 Railway가 제공하므로 고정값을 넣지 않습니다. Dockerfile에 `HOST=0.0.0.0`, `DATA_FILE=/data/game.sqlite`, `COOKIE_SECURE=1`이 들어 있습니다.
6. 배포가 성공하고 상태가 정상이라면 서비스 설정의 **Networking → Public Networking → Generate Domain**에서 공개 도메인을 생성합니다. UI 명칭은 Railway 업데이트에 따라 다를 수 있습니다. 타깃 포트가 필요하면 배포 로그의 `FIRST TEAM listening on port ...` 숫자를 사용합니다.
7. 생성된 `https://…up.railway.app` 주소를 엽니다. 캐릭터 슬롯을 저장한 뒤 방을 만들고, 친구에게는 같은 웹 주소와 방 초대코드를 함께 보냅니다. 친구는 자기 브라우저에서 같은 팀의 다른 포지션 캐릭터로 참가합니다.

배포 전 Railway 화면의 요금과 이용 한도를 확인하세요. 서버 실행과 영구 저장에 비용이 생길 수 있으며 무료 제공을 보장하지 않습니다. 이 게임은 생성형 AI를 호출하지 않습니다.

이 클라우드에서 사용하던 세이브는 새 호스팅으로 자동 이전되지 않습니다. 새 호스팅에서는 새 시즌으로 시작하며, 기존 세이브가 필요하면 별도의 DB 이전이 필요합니다. API 키·비밀번호를 채팅이나 저장소에 넣을 필요는 없습니다. 웹사이트의 GitHub 연결 흐름을 사용합니다.

배포 뒤에는 실제 공개 HTTPS 접속, 재시작 후 저장 복원, 독립된 두 브라우저의 같은 방 진행을 확인해야 합니다. 현재 검증은 로컬 서버에서 완료했으며 Railway 배포 성공을 확인한 상태는 아닙니다.
