# 세트별 선수 기록과 진영

중계와 다시보기는 `public/set-records.js`의 같은 렌더러를 사용한다. 선수 기록과 밴픽을 블루/레드 두 칸으로 배치하고, 현재 선택한 세트의 `draft.assignment`로 정렬한다. KDA는 중계 API의 공개된 교전 집계만 사용한다. 팀 A/B는 시리즈 점수와 이벤트 배열의 안정적인 식별자로 남으며, 시리즈 헤더에서 고정 BLUE/RED 표시는 제거한다.

새 시뮬레이션의 `draftVersion=1`:

- 첫 세트 선택권은 기존 경기의 사전 배정(teamA, 대회별 `selectionReason`)을 사용한다.
- 다음 세트는 직전 패배 팀에 선택권을 준다. 매번 무조건 교대하는 방식은 아니다.
- 일반 경기는 선택권 팀이 블루 진영을 자동 선택하며 퍼스트픽도 함께 가진다. 별도 퍼스트픽 선택권은 없다고 표시한다.
- RoFS 경기(`selectionRight=true`)는 기존처럼 선지명 팀이 퍼스트픽을 자동 선택하고, 상대 팀은 남은 선택인 진영을 맡아 블루를 자동 선택한다. 따라서 레드팀이 퍼스트픽을 가질 수 있다.
- 진영에 따른 추가 능력치 보정이나 새로운 RNG 호출은 없다. 실제 드래프트 우선 팀과 표시하는 퍼스트픽 팀이 같다.

이전 경기에는 진영 선택권을 임의로 채우지 않는다. 기존 A/B 진영 배치와 실제 기록된 RoFS 퍼스트픽을 표시하고, 빠진 선택권은 ‘기록 없음’으로 안내한다.

이미 진행 중인 중계의 전략 재개는 저장된 첫 세트의 assignment 버전으로 `season.matchDraftVersions`를 고정한다. 버전 없는 저장은 `draftVersion=0`으로 재생성하여 기존 드래프트·RNG·경기 결과를 보존한다. 공개된 세트는 기존 원본을 계속 사용한다.

검증: `npm test`, `npm run check`, 임시 DB/서버에서 `DATA_FILE=/tmp/파일.sqlite BASE_URL=http://127.0.0.1:포트 node test/set-records-browser.mjs`.
